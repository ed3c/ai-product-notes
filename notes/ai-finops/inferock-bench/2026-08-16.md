# Inferock Bench｜2026-08-16

## 繁體中文

### 產品與日期

- Product Hunt：2026-08-15 當日 #1，251 points；頁面在本次監控時仍標示 `Launching today`。
- 產品：`inferock-bench`，local proxy，放在應用程式與 OpenAI / Anthropic / Gemini / OpenRouter-shaped API calls 之間，記錄 per-call usage、failures、retries，產生獨立 billing-integrity receipt。

### Target customer 與 pain

ICP 是 multi-model AI SaaS、agent teams、AI agencies 與 FinOps / platform teams。核心 pain 不是「不知道總 token 數」，而是 monthly provider invoice 無法回答某個費用跳升究竟來自合法成長、failed calls、silent retries、cache-discount miss、truncation 或 token-count discrepancy。

Product Hunt 討論本身提供了強 problem evidence：使用者描述 multi-model agent bills 無法解釋，以及 timeout / failed-call costs 難以追溯。不過這仍是 qualitative demand，不能當成已付費需求。

### 商業模式、pricing 與 WTP

`inferock-bench` 目前免費。Inferock hosted/managed product 採 invite 模式，主張 accountable inference 與 eligible-failure credits，但本次沒有取得公開 recurring price。Maker 在 Product Hunt 明確回答目前**還沒有**成功以 receipt 向 provider 取得 credit 的案例，因此不能把 dispute recovery 當成已驗證 ROI。

內部 WTP 判斷：**6/10**。Pain 與 cost attribution 很直接，但目前 payment evidence 弱。

### Competition / Gap

鄰近產品包括 Langfuse、Helicone、LiteLLM、provider dashboards 與 cloud FinOps。較窄的 gap 是：

`provider-visible request/response evidence → independent call-level receipt → invoice reconciliation → dispute-ready evidence pack`

這和一般 observability 的差別在於把 trace 連到可審計的 cost / billing claim，而不是只呈現 latency、tokens 與 errors。

### Technical / operational barriers

- Provider compatibility rewrite 必須記錄 post-compatibility request body，否則 evidence 可能不是 provider 真正看到的 payload。
- Streaming truncation、cache semantics、retries、provider-native refusal 與 tokenizer approximation 需要不同 evidence grade。
- API keys、prompt/response payloads 與 PII 必須 local-first / redacted；不能為了 FinOps 收集不必要的 raw customer trajectories。
- False billing accusation 具有信任與法律風險，產品應輸出 `observed discrepancy / invoice-check exposure`，不是無證據宣稱 provider overcharged。

### Solopreneur MVP：LLM Billing Reconciliation & Dispute Pack

建議第一版不是再做一個通用 LLM observability dashboard，而是：

1. OpenAI / Anthropic / Gemini / OpenRouter-compatible proxy 或 OTel collector。
2. 每 call canonical receipt：provider、model、usage、retry lineage、status、latency、observed charge context。
3. 每日 / 每月 invoice reconciliation：expected vs observed，異常分類與 confidence。
4. 產生 dispute-support bundle：immutable request IDs、timestamps、receipt hashes、affected call list。
5. 預設不保存 raw prompt；只保存 billing 所需 metadata，必要內容以 opt-in redaction policy 處理。

Pricing hypothesis：**US$49–299/month**，高量 enterprise 可按 observed spend / event volume 計價；不建議一開始抽成 disputed savings，因 recovery 尚未被驗證。

### 兩週驗證

- 找 5 個每月 multi-provider inference spend ≥ US$1K 的 teams。
- 匯入或代理至少 50k calls。
- 指標：可解釋 cost delta、retries / failed-call waste、invoice mismatch、reconciliation false-positive rate。
- Gate：至少 3/5 teams 發現原本不知道且可採取行動的 cost anomaly；至少 2 家接受 US$99/month paid pilot。
- 若只有「dashboard 很好看」但沒有 paid demand，維持 `VALIDATE`。

### 結論

產品問題本身值得付費，但目前最強證據是 cost pain + launch engagement，而不是 recurring revenue。建議把機會定義成 **AI FinOps reconciliation / evidence**，不要只複製 `inferock-bench`。目前決策：**VALIDATE**。

## English

Inferock Bench is a local, provider-compatible measurement proxy that turns each LLM API call into a billing-integrity receipt. The commercial wedge is not generic observability; it is reconciling provider spend with request-level evidence and producing a dispute-ready evidence pack.

The Product Hunt launch reached #1 on August 15, 2026, but the product is free and the maker explicitly said there is not yet a provider-credit recovery case to cite. That makes the pain credible while leaving paid demand and recovery ROI unproven.

The best two-week MVP is a privacy-bounded multi-provider reconciliation layer: canonical call receipts, retry lineage, anomaly classification, invoice reconciliation and exportable evidence. Target teams spending at least US$1K/month across multiple providers and require two US$99/month paid pilots before moving beyond `VALIDATE`.

The open-asset decision is scoped. `@inferock/measure` is Apache-2.0 and qualifies as a `PASS` code asset. The full `inferock-bench` CLI is FSL-1.1-ALv2 and therefore remains `CONDITIONAL`; no model, dataset or trajectory rights are inferred from the package license.
